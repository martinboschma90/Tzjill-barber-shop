# Tzjill Barber & Lounge — site audit

**Date:** 18 September 2026  
**Live preview:** [https://tzjill-barber-shop.vercel.app/](https://tzjill-barber-shop.vercel.app/)  
**Customer domain today:** [https://www.tzjill.nl/](https://www.tzjill.nl/) (still the old WordPress site on LiteSpeed)  
**Audience:** walk-through with the owner + Flow Mates / Viraal implementers  
**Scope:** marketing site stability (mobile + desktop) and worthwhile code cleanup. No fixes in this PR.

---

## Executive summary

**Verdict: shaky.**

The public shop pages *look* like a finished barber site. Home, prijzen, lookbook, products, team, over-ons and contact render. Images on those routes resolve. Salonhub’s widget URL is live. Mobile hero + hamburger work.

Under that surface the repo is still a **Notype / Flow Mates artist-agency CMS** with a Tzjill skin. Several leftovers are **live and owner-visible**, not just in source:

| What a visitor can hit today | What they get |
|---|---|
| `/faq` | English “Promoter FAQ” about booking DJs / festival lineups |
| `/cms` | Unlocked Flow Mates CMS dashboard (“Lokaal ADMIN”, 12 seed artists) |
| Any unknown URL | Silent redirect to home (no 404) |
| View-source / first HTML | Canonical + robots still say `www.notype-mgmt.com` |
| After JavaScript | Canonical becomes `https://www.tzjill.nl/…` — the **old WordPress** site |

So: the shop can be shown to the owner as a visual preview, but it is **not ready to point `tzjill.nl` at**, and it is **not safe to leave `/cms` on a public Vercel URL**.

### Top 5 priorities

1. **Lock the CMS** on the preview host (or take `/cms` off the public deploy) and decide the real go-live host before Google indexes the Vercel URL.
2. **Fix the three-host SEO mess** (`notype-mgmt.com` in static tags / robots / sitemap, `www.tzjill.nl` after JS, `*.vercel.app` as the actual site). Do this *before* a domain cutover.
3. **Hide or rewrite `/faq`.** It currently publishes Notype promoter copy. Homepage FAQ is already the correct barber copy.
4. **Cut hero / lookbook weight.** Homepage hero is an **11 MB MP4** with `preload="auto"`, and two PNGs are 650–750 KB. This is the main mobile stability + LCP risk.
5. **Desktop nav + sticky “Afspraak”.** Eight uppercase links crowd the 1440px header; the floating CTA covers Salonhub chrome and FAQ content.

## Stack & project structure

Same family as other Flow Mates / Viraal sites (Vite SPA + `/cms` + Supabase JSON store), forked from Notype.

| Layer | Choice |
|---|---|
| App | React 19 + React Router 7, client-rendered only |
| Build | Vite 8, TypeScript, Tailwind 4, oxlint |
| Motion | framer-motion (hero parallax, reveals) |
| Hosting | Vercel static + serverless `api/*` |
| CMS | Flow Mates shell at `/cms` (alias `/admin`) |
| Backend (intended) | Supabase (`@supabase/supabase-js`) — **not configured on the live preview** |
| Booking (shop) | Salonhub iframe (`widget.salonhub.nl/a/tzjill/tzjill/link.html`) |
| Booking (legacy CMS) | Promoter request form + `/api/booking-request` → `martin@notype-mgmt.com` |
| Analytics | `@vercel/analytics` (delayed) + custom RUM (`/api/rum`, `/api/site-speed`) |
| Fonts | `@fontsource/inter` + `@fontsource/archivo-black` bundled in CSS |

**Layout (short):**

```
api/                 Vercel functions (booking, CMS users, live/speed, RUM)
public/              brand, lookbook, reviews, robots, sitemap
src/pages/           public routes + CMS login
src/components/      shop UI (hero, booking, home, layout)
src/cms/             Flow Mates editors, media library, artist roster
src/data/            hardcoded shop copy, menu, lookbook, leftover artists
supabase/            migrations still keyed as notype-*
```

Public routes: `/`, `/prijzen` (`/menu` →), `/lookbook`, `/products`, `/collabs`, `/team`, `/over-ons` (`/about` →), `/contact`, `/booking`, `/faq`.  
`/artists/:slug` still exists from the agency template. Unknown paths → `/`.

There is **no SSR**. Title, description and canonical in `index.html` are what non-JS crawlers see.

## Findings

Severity: **Critical** = live risk or wrong-brand in public; **High** = will hurt go-live / mobile / SEO; **Medium** = worth fixing this cycle; **Low** = cleanup.

---

### Critical

#### C1 — `/cms` is open to the world on the preview host

**What’s wrong:** Live `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` are empty (confirmed in the injected boot script). `CmsAuthGate` treats “Supabase not configured” as **no login required** and grants a local admin role. Visiting `/cms` redirects to `/cms/dashboard`. The dashboard shows “Lokaal ADMIN”, 12 seed **artiesten**, media library, settings, and a reset/danger zone.

**Where:**  
`src/cms/auth/CmsAuthGate.tsx`  
`src/cms/auth/AuthProvider.tsx` (`authRequired: isSupabaseConfigured`)  
`src/lib/supabaseEnv.ts`  
`vite-plugin-public-boot.ts` (live HTML: `SUPABASE_URL = ""`)

**Why it matters:** Anyone with the Vercel URL can open the CMS. Edits persist in that browser’s `localStorage` only (keys `tzjill-cms-content-v1`, etc.), so they do not publish for everyone — but the owner’s draft content, reset actions, and the fact that this is an unlocked admin are all public.

**Suggested fix:** Do not ship `/cms` without auth. Either set Supabase env + require login, or gate/remove the CMS route on the production/preview deploy. Add a Vercel password or IP allowlist on the preview in the meantime.

---

#### C2 — Three hosts fight each other for SEO (Notype, WordPress, Vercel)

**What’s wrong:**

| Signal | Value today |
|---|---|
| `index.html` canonical (no JS) | `https://www.notype-mgmt.com/` |
| `public/robots.txt` Host + Sitemap | `https://www.notype-mgmt.com` |
| `public/sitemap.xml` `<loc>` | `https://www.notype-mgmt.com/` plus `/about` (old path), `/contact`, `/booking`, `/faq` |
| After React (`PublicSeo`) | `https://www.tzjill.nl{path}` because `publicSiteUrl` is empty |
| Actual site | `https://tzjill-barber-shop.vercel.app/` |
| `www.tzjill.nl` | **Different site** — WordPress / PHP 8.1 |

CMS settings UI still tells editors to use `https://www.notype-mgmt.com`.

**Where:**  
`index.html`  
`public/robots.txt`  
`public/sitemap.xml`  
`src/components/layout/PublicSeo.tsx`  
`src/cms/editors/SettingsEditor.tsx`  
`src/cms/content.ts` (`publicSiteUrl`)

**Why it matters:** If Google indexes the Vercel preview, it will either credit Notype or the old WordPress domain. After a DNS cutover, the same bugs will either keep sending equity to Notype or create a canonical loop. Sitemap also lists `/about` (redirects) and `/faq` (wrong content), and omits `/prijzen`, `/lookbook`, `/team`, `/over-ons`, `/products`.

**Suggested fix:** One source of truth for the public origin (env, e.g. `VITE_PUBLIC_SITE_URL`). Bake it into `index.html`, robots, sitemap, and `PublicSeo`. Until `tzjill.nl` points here, set `noindex` on the Vercel host. Expand the sitemap to the real Dutch routes.

#### C3 — `/faq` is live Notype promoter content

**What’s wrong:** `/faq` is reachable (sitemap even lists it). Live H1 is **“Promoter FAQ”**. Tabs: Regular / Europe / International Bookings, Payments & Booking Terms. Questions are “How can I request an artist booking?”, festival programming, etc. Defaults come from the agency seed (`faqVisible: true`, `faqTitle: 'Promoter FAQ'`).

Homepage FAQ (`HomeFaq`) is the correct Dutch barber copy (Salonhub, te laat, kids). The dedicated page ignores that.

**Where:**  
`src/data/faq.ts`  
`src/cms/content.ts` (`faqTitle`, `faqIntro`, `faqCategories`)  
`src/pages/FaqPage.tsx`  
`src/App.tsx` (`/faq` route)

**Why it matters:** Owner-visible wrong brand. If the URL is indexed (sitemap + `index, follow`), Tzjill will rank for promoter/artist booking queries.

**Suggested fix:** Set `faqVisible` false *or* replace defaults with the homepage FAQ (or a short shop FAQ). Remove `/faq` from the sitemap until the copy is Tzjill.

### High

#### H1 — Hero video is ~11 MB and loaded twice, with `preload="auto"`

**What’s wrong:** `public/brand/hero.mp4` is **10.9 MB**. `Hero` plays it full-viewport with `preload="auto"`. `Welcome` plays the **same file** again in a side card (`preload="metadata"`). About also embeds `/brand/hero.mp4`. Boot script still preloads a YouTube thumb (`i.ytimg.com/vi/xXt3erMFs8w/…`) on `/about` even though About no longer uses that YouTube clip.

**Where:**  
`src/components/hero/Hero.tsx`  
`src/components/home/Welcome.tsx`  
`src/pages/AboutPage.tsx`  
`vite-plugin-public-boot.ts` (`preloadAboutThumb`)  
`public/brand/hero.mp4`

**Why it matters:** This is the LCP element on mobile. On a mid-range phone / 4G the hero will stall, heat the radio, and compete with the logo preload. Two decoders for one file is wasted work. CLS is mostly contained (fixed `min-h-[100svh]`), but late video paint still feels unstable.

**Suggested fix:** Compress to a short loop (target well under 1.5 MB, plus a poster). `preload="none"` or `"metadata"`; poster-only on `max-width: 767px` or `saveData` / `2g` (About’s unused YouTube helper already has this idea). Do not play the file twice on the homepage — image in Welcome is enough.

#### H2 — Lookbook / product images are heavy and not cached

**What’s wrong:**

| File | Size | Used on |
|---|---|---|
| `/lookbook/05.png` | 746 KB | Welcome, About, Products, Instagram carousel, Contact banner |
| `/lookbook/06.png` | 660 KB | Lookbook, Products, Collabs, Instagram |
| `/lookbook/01.jpg`–`04.jpg` | 170–275 KB | Treatments, team fallbacks, products, IG |

`vercel.json` sets long cache only for `/brand/*` and `/assets/*`. Lookbook and reviews get `max-age=0, must-revalidate`. Instagram + product grids use raw `<img>`, not `OptimizedImg` (that helper only rewrites Supabase/Unsplash URLs; local files pass through).

Review **videos** (`public/reviews/*.mp4`, ~700 KB each) are in the deploy but **never rendered** — `Testimonials` only uses the stills.

**Where:**  
`public/lookbook/`  
`src/components/home/InstagramFeed.tsx`  
`src/pages/ProductsPage.tsx`  
`src/pages/LookbookPage.tsx`  
`vercel.json`  
`src/data/reviews.ts` vs `src/components/home/Testimonials.tsx`

**Why it matters:** Repeat visits re-download the heaviest photos. Homepage “Instagram” shows three large stills at once. Mobile audit saw lookbook images still at `naturalWidth === 0` after 1.5s — weight, not 404s.

**Suggested fix:** Convert 05/06 to compressed JPEG/WebP (~80–120 KB). Add `/lookbook/` and `/reviews/` to the immutable cache rule (or hash filenames). Drop unused review MP4s from the deploy, or use them on purpose.

#### H3 — Desktop nav is overcrowded; sticky CTA covers booking UI

**What’s wrong:** `publicNav` is eight items (Home, Prijzen, Lookbook, Products, Collabs, Team, Over ons, Contact) at `lg+`, all `type-ui` (uppercase, wide tracking) plus a 54px logo. At 1440×900 the labels sit on top of each other (`LOOKBOOK`/`PRODUCTS`, `OVER ONS`/`CONTACT`).

The floating **Afspraak** chip (`StickyContactBar`) is `fixed bottom-5 right-4 z-[55]`. It sits on FAQ answers, lookbook photos, and the Salonhub “Volgende” controls on `/booking`.

**Where:**  
`src/data/nav.ts`  
`src/components/layout/Navbar.tsx`  
`src/components/layout/StickyContactBar.tsx`  
`src/components/booking/SalonhubWidget.tsx`  
`src/pages/BookingPage.tsx`

**Why it matters:** Owner asked for desktop + mobile stability. The header is the first desktop defect; the CTA is the first booking defect. On a phone the chip is useful; on `/booking` it fights the widget it is meant to open.

**Suggested fix:** Drop Home from the bar (logo already goes home). Move Products/Collabs into the overlay or footer. Hide the sticky chip when the Salonhub dialog is open and on `/booking`. Add `pb-safe` / extra footer padding so the last price row is not under the chip.

---

#### H4 — Salonhub works on `/booking`, but the overlay path is easy to miss

**What’s wrong:** `https://widget.salonhub.nl/a/tzjill/tzjill/link.html` returns 200 and the `/booking` iframe loads (live: no-show policy, “powered by salonhub”). The global overlay (`SalonhubWidget`) only mounts after `openSalonhub()` / `#afspraak`. It has no focus trap, no `iframe` sandbox/`loading`, and the sticky button’s accessible name is the same as homepage FAQ filters (“Afspraak”), so a real user — and our first automation pass — can click the filter instead of booking.

**Where:**  
`src/data/site.ts` (`SALONHUB_BOOKING_URL`)  
`src/components/booking/SalonhubWidget.tsx`  
`src/components/booking/BookButton.tsx`  
`src/lib/salonhub.ts`

**Why it matters:** Booking is the conversion path. Overlay + full page + sticky chip is three entries to one third-party iframe. Third-party cookies / ITP can still blank the iframe on Safari; there is no fallback beyond “go to `/booking`”.

**Suggested fix:** Keep one primary path (overlay *or* `/booking`, not both competing). Unique names (`Afspraak maken` vs FAQ “Afspraak”). Trap focus in the dialog; `loading="lazy"` on the page iframe; fallback link to the Salonhub URL if the iframe is empty.

#### H5 — Fork leftovers will break a real `tzjill.nl` cutover

**What’s wrong:** API allowlists and defaults are still Notype:

- CORS: only `notype-mgmt.com` and `no-type-mgmt*.vercel.app` (`api/http-security.mjs`). `*.vercel.app` Host is allowed, so today’s preview works; **`tzjill.nl` is not**.
- Speed/live probes default to `https://www.notype-mgmt.com` (`api/site-live.js`, `api/site-speed.js`, CMS dashboard).
- CMS invite redirect: `https://www.notype-mgmt.com/cms/login` (`api/cms-users-lib.mjs`).
- Dev proxy: `https://no-type-mgmt.vercel.app` (`vite.config.ts`).
- Booking-request mail: `martin@notype-mgmt.com` / Resend from `NOTYPE MGMT` (`src/data/booking.ts`, `api/booking-request-lib.mjs`).
- WhatsApp default: `+31 36 236 53232` and “Hi NOTYPE MGMT…” (`src/data/whatsapp.ts`).
- Hardcoded owner email `martin@viraal.media` (`src/cms/auth/AuthProvider.tsx`).
- Boot + SQL cache keys: `notype-public-artists-v3` vs React `tzjill-public-artists-v3` (`vite-plugin-public-boot.ts`, `src/cms/storageKeys.ts`, `supabase/migrations/20260827120000_cms_json_store.sql`).
- Crash screen brand: **NOTYPE** (`src/components/ErrorBoundary.tsx`).

**Why it matters:** The day DNS moves, booking/CMS APIs can 403, health checks will keep hitting Notype, and a React crash will show the wrong company. The key mismatch means a later Supabase attach will fetch empty artist cache from the boot script while the CMS writes `tzjill-*`.

**Suggested fix:** Replace host allowlists with `tzjill.nl` + this Vercel project. Align all storage keys. Point mail/WhatsApp at `info@tzjill.nl` / `058 844 7025`. Drop the Viraal owner shortcut or make it a role in `user_roles`.

#### H6 — Soft 404s and inner-page titles

**What’s wrong:** `UnknownPublicPath` always `<Navigate to="/" replace />`. `/this-does-not-exist` becomes home with `200` + homepage canonical. `PublicSeo` only sets `document.title` on `/`; every other public page stays **“Tzjill Barber Shop”**. No `og:image`, no per-page description, no JSON-LD LocalBusiness.

**Where:**  
`src/App.tsx`  
`src/components/layout/PublicSeo.tsx`  
`index.html`

**Why it matters:** Soft 404s waste crawl budget and can associate junk URLs with the homepage. Share cards from `/prijzen` or `/contact` look like the home tab.

**Suggested fix:** A real `/404` (and `status` if you later add an edge rewrite). Title template: `{Page} — Tzjill Barber & Lounge`. Unique descriptions + one OG image (logo or hero poster). Optional LocalBusiness JSON-LD (address, phone, opening hours already exist in `src/data/site.ts`).

### Medium

#### M1 — “Instagram” is a lookbook carousel, not Instagram

**What’s wrong:** `InstagramFeed` autoplays `lookbookImages` and links every tile to `instagram.com/tzjill.barber.lounge`. No Graph API, no embeds. Artist-page Instagram helper (`src/cms/artistInstagram.ts`) is unused on the shop. Tiles have no `width`/`height`; off-center slides are still clickable links.

**Where:** `src/components/home/InstagramFeed.tsx`, `src/data/lookbook.ts`, `src/data/site.ts`

**Why it matters:** Fine as a lookbook teaser if labelled honestly. As “Instagram” it will go stale the moment the shop posts something new. Autoplay + pointer-drag is extra client JS on the homepage.

**Suggested fix:** Rename to “Looks” / reuse Lookbook, or wire 6 CMS permalinks (the artist carousel already parses `/p/` and `/reel/`). Respect `prefers-reduced-motion` (already) and pause when off-screen.

#### M2 — Newsletter and contact are mailto-only

**What’s wrong:** Both forms `preventDefault` and set `window.location.href = mailto:info@tzjill.nl`. On iPhone this opens Mail; on desktop without a mail client it feels broken. Success copy assumes the message was sent. No server endpoint, no spam protection (not needed for mailto), no newsletter list.

**Where:**  
`src/components/home/Newsletter.tsx`  
`src/components/contact/ContactForm.tsx`

**Why it matters:** Owner will think “the form doesn’t work” on a shop iPad / Chrome. Newsletter implies a list; there isn’t one.

**Suggested fix:** For v1, replace newsletter with an Instagram + WhatsApp / tel CTA. For contact, keep mailto as fallback but add a small `/api/contact` (Resend to `info@tzjill.nl`) or a Salonhub-only CTA. Do not claim “we zetten je op de lijst” until a provider exists.

#### M3 — Legal / privacy links are placeholders and not even in the footer

**What’s wrong:** `site.legalLinks` is Privacy / Terms / Cookies → `#privacy` `#terms` `#cookies`. `Footer.tsx` never renders them. No privacy page, no cookie banner, Vercel Analytics + RUM still run.

**Where:** `src/data/site.ts`, `src/cms/content.ts`, `src/components/layout/Footer.tsx`, `src/lib/siteRum.ts`, `src/App.tsx`

**Why it matters:** Dutch shop + analytics. Low legal exposure vs a webshop, but the CMS still lets someone add those hashes. Analytics loads after 1.2s (good) but is not documented to the visitor.

**Suggested fix:** One `/privacy` (or footer text) covering Salonhub, Google Maps, Vercel Analytics, Instagram. Only add a banner if you store a newsletter list.

#### M4 — `/faq` contrast is broken on the dark theme

**What’s wrong:** `FaqHub` uses `text-ink`. Public theme is dark (`--color-ink: #f5f5f5`). The page wraps the hub in a **white** card (`bg-white`). Result: near-white questions on white — confirmed on desktop and mobile screenshots. Homepage FAQ uses explicit cream/white tokens and is readable.

**Where:** `src/components/faq/FaqHub.tsx`, `src/pages/FaqPage.tsx`, `src/index.css`

**Why it matters:** Even after C3, if `/faq` stays, it is not readable. Same hub is used in CMS preview.

**Suggested fix:** Scope FAQ ink to the white panel (`text-[#2c241c]` or a `.page-panel` class that already exists in `index.css` but is unused here).

#### M5 — Mobile menu contrast and two Afspraak buttons

**What’s wrong:** Overlay inactive links are `text-ink/35` on a dark blur — visually ~gray-40 on black (fails a casual WCAG check). Active “Home” is fine. Overlay **and** sticky bar both show Afspraak. No Escape / focus trap / `aria-hidden` on the page behind the overlay.

**Where:** `src/components/layout/MenuOverlay.tsx`, `src/components/layout/AppShell.tsx`

**Why it matters:** Eight large links are usable, but inactive items are hard to see. Two CTAs is noisy, not broken.

### Low

#### L1 — Notype brand files still in `public/brand/`

Wordmarks, seal, stacked lockup, 118 KB `favicon.png`, README for “No Type brand assets”. Public UI uses `tzjill-logo.png`. Extra bytes on every clone/deploy; mix-up risk if someone points `Logo` at the old files.

#### L2 — Agency machinery still in the public router

`/artists/:slug`, `BookingForm` (promoter), music player, reels, WhatsApp artist CTAs. Lazy-loaded, so they are mostly bundle risk + CMS surface, not homepage weight. CMS dashboard still leads with **Artiesten**.

#### L3 — Missing `.env.example`

README says `cp .env.example .env.local`. File is not in the repo (gitignore allows `!.env.example` but nothing is committed). Next developer will not know which keys the preview needs.

#### L4 — Error / login chrome still says Flow Mates / NOTYPE

CMS document title: “Flow Mates CMS”. Login gate copy: “Flow Mates CMS laden…”. Public crash: “NOTYPE”. Fine internally; wrong if a customer hits it.

#### L5 — Accessibility basics

No skip link. Many decorative images correctly `alt=""`, but product/collab cards also have empty alt while the name is a heading (OK if the heading is adjacent). Salonhub iframe title is good. Carousels have `aria-roledescription` but no live slide announcements. Focus rings are missing on most pills (only artist cards define `focus-visible`).

#### L6 — `Access-Control-Allow-Origin: *` on Vercel static responses

Default for this project. Low risk for a brochure site; do not put secrets in the static bundle. Anon key, when set, is already public-by-design — still rotate if this preview was ever shared widely with a real key (today the key is empty).

#### L7 — Hydration

Create-root CSR only (`src/main.tsx`). No RSC/SSR hydration mismatch. Theme script in `index.html` is the right pattern. Not a bug.

## CMS / admin (brief)

The CMS is a full Flow Mates console: page editors (home, prijzen, lookbook, products, collabs, team, over-ons, contact, footer), media library (IndexedDB + optional Supabase storage), traffic / PageSpeed dashboard, user roles, artist roster.

**For this shop it is larger than the site.** Deep CMS audit is not worth it until C1 is closed. Notes only:

- Editors for Tzjill pages exist (`src/cms/editors/*`, `src/cms/panels/*`) and match the public routes.
- Artist / booking-request / FAQ-promoter / WhatsApp surfaces are leftover agency product.
- Health meter scores the **empty** `publicSiteUrl` and still talks about artists (live dashboard: SEO 72, “12 artiesten”, site-live 401 against `notype-mgmt.com`).
- `supabase/README.md` still documents `notype-cms-content-v1` and a Phase 3.1 “temp anon artist writes” path. Do not run that on a Tzjill project.
- `.env.example` is missing; required keys when you do attach a backend: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, plus server `SUPABASE_SERVICE_ROLE_KEY`, `CRON_SECRET`, Resend, PageSpeed as needed.

**Recommendation:** treat CMS as “internal, lock it” for this walk-through. A later ticket can slim the shell to shop pages only.
